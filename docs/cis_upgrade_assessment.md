# APA-CIS Climate Information Service Upgrade Assessment

Date: 2026-06-10  
Coverage: Batanes, Cagayan, Isabela, Nueva Vizcaya, Quirino  
Users: DA RFO 02, LGUs, AMIA/APA sites, municipal agriculturists, planners, farmer advisory teams

## 1. Current System Assessment

### Architecture Summary

| Area | Current Implementation |
|---|---|
| Frontend | Static HTML/CSS/JavaScript app in `frontend/`; module tabs for Climate Dashboard, Map Layers, Agri-Operations Advisory, Municipal Profile, and Planning Dashboard. |
| Map library | Leaflet 1.9.4 from CDN. Current map layers are point GeoJSON layers by municipality centroid. |
| Charts/UI | Vanilla JS modules. No build step. No framework dependency. |
| Backend | No live backend service in `api/`. Current data delivery is static JSON/GeoJSON generated by Python and read by browser fetch calls. |
| Database | None currently. Configuration and outputs are JSON files under `config/` and `data/`. |
| Data pipeline | Python ETL under `scripts/`: NASA POWER fetch, PAGASA semi-automated ingest, indicator computation, advisory engine, weekly summary, and master `run_pipeline.py`. |
| Data files | `config/municipalities.json` contains municipal centroids, climate type, elevation, and irrigation status. Processed output directories are defined, but current local checkout has no populated `data/processed` or `data/geospatial` files. |
| API calls | NASA POWER API is implemented. PAGASA is semi-automated through PDFs, manual entry, and public page scraping. No CHIRPS/GSMaP/ERA5 automated fetcher yet. |
| Dashboards | Climate indicators table, summary cards, advisory panel, map layer selector, municipal profile, planning dashboard. |
| Deployment | GitHub Actions daily pipeline and GitHub Pages static hosting are configured. |
| Tests | Indicator unit tests exist in `tests/test_indicators.py`. Local validation could not run in this environment because `pytest` is not installed. |

### Current Limitations

- The system is strong for a first static CIS: it already translates weather data into indicators and advisories.
- It is still centroid-based; municipal boundary polygons, barangay/AMIA sites, irrigation polygons, crop area, farmer exposure, and hazard overlays are not yet integrated.
- There is no database/API layer, so history, audit trails, dashboards, permissions, and query performance will become difficult as data grows.
- Short-term forecasts, 3-10 day outlooks, official PAGASA forecast products, typhoon bulletins, thunderstorm advisories, and seasonal outlooks are not yet first-class structured data.
- Crop calendars are simplified and not linked to actual planting reports, RSBSA exposure, irrigation service areas, or AMIA village monitoring.
- Advisory rules are transparent but need validation by DA/PAGASA/MAO domain reviewers and local threshold calibration.
- Text files contain visible mojibake in some places when read in PowerShell, so encoding/rendering should be checked before public release.
- No production data quality dashboard exists for missing values, stale products, failed fetches, and suspicious outliers.

## 3. Missing Weather, Climate, and Agriculture Analyses

Immediate operational products:

- Short-term weather advisories for rainfall, heat, wind, thunderstorm, and typhoon impact.
- 3-10 day outlooks with advisories for planting, fertilizer, spraying, irrigation, harvest, and drying.
- Rainfall forecast classes: dry, light, moderate, heavy, very heavy, extreme.
- Temperature, humidity, wind, and solar radiation summaries by municipality.
- Heat stress risk for field workers, livestock, and crop reproductive stages.
- ETo and crop water deficit using crop coefficient by stage.
- Field workability using rainfall, soil wetness proxy, wind, and near-term forecast.
- Seasonal rainfall outlook, percent of normal, rainfall anomaly, ENSO watch, drought/dry spell, wet spell, onset/cessation.
- Municipality-level climate-type advisories that adjust planting windows by Type I/II/III/IV climate and elevation.

Agriculture analytics:

- Rice/corn planting window suitability by municipality, season, rainfall onset, and forecast.
- Crop-stage drought/flood/heat/disease risk using actual planting reports where available.
- Pest and disease triggers: rice blast, bacterial leaf blight, sheath blight, brown planthopper, fall armyworm, corn fungal diseases.
- Harvest/postharvest drying risk from rainfall, humidity, wind, and solar radiation.
- Rainfed vs irrigated vulnerability using irrigation service area overlays and crop area.
- Unplanted area risk where planting window is closing and rainfall is below normal.
- Production loss early warning from crop area, stage, hazard severity, and exposure.
- Crop insurance trigger support using event date, location, hazard, duration, crop/stage, and affected area.
- Municipal priority ranking for advisories and DA intervention targeting.

Planning analytics:

- APA municipality dashboard: risk, exposure, intervention status, advisories, and current data freshness.
- AMIA village monitoring: site-level crop status, water source, hazard exposure, advisories issued.
- DA intervention targeting: seed buffer, water pumps, small water impounding, irrigation repair, mobile dryers, storage, mechanization.
- Overlays: rice/corn area, RSBSA/smallholder farmers, irrigation service areas, hazard layers, crop calendars, APA/AMIA sites.
- Climate-resilient investment priorities: irrigation, water harvesting, seed buffer, mechanization, storage, dryers, flood-safe logistics.

## 4. Recommended Architecture

### Phase 1: Static GitHub Pages Mode

- Keep the current GitHub Pages app.
- Python ETL writes JSON/GeoJSON files daily.
- Browser fetches static outputs.
- Best for quick publication, transparent operation, and low cost.

### Phase 2: Supabase/PostGIS Mode

- Supabase PostgreSQL/PostGIS becomes the source of truth.
- Python ETL writes both database rows and static JSON exports.
- Frontend reads public views through Supabase API or generated static files.
- Use Row Level Security for internal-only layers such as RSBSA/farmer exposure.

### Phase 3: API Service Mode

- Add FastAPI only if custom business logic, authentication, report generation, or non-public endpoints outgrow Supabase views.
- Keep explainable rule outputs and source lineage.

## 6. Indicator Computation Logic

| Indicator | Logic |
|---|---|
| Percent of normal rainfall | `observed_period_rainfall / climate_normal_period_rainfall * 100` |
| Rainfall anomaly | `observed_period_rainfall - climate_normal_period_rainfall` |
| Dry day | Daily rainfall `< 1.0 mm` |
| Consecutive dry days | Current streak of dry days ending on latest valid day |
| Wet day | Daily rainfall `>= 1.0 mm` |
| Consecutive wet days | Current streak of wet days ending on latest valid day |
| Dry spell watch | CDD `>= 10` |
| Dry spell warning | CDD `>= 14` |
| Critical drought watch | CDD `>= 21`, higher priority in rainfed areas |
| Heat stress | Approximate WBGT from Tmax and RH; later include solar and wind |
| ETo | FAO-56 Penman-Monteith where full variables are available |
| Irrigation demand | `max(0, crop_coefficient * ETo - effective_rainfall)` |
| Field workability | Rainfall 24h/48h, soil wetness proxy, wind, dry spell status |
| Crop-stage risk | Max hazard component plus modifiers for heat/disease/stage/exposure |
| Municipal priority | Hazard severity + crop exposure + rainfed share + vulnerable farmers + active advisories |

## 7. Advisory Rule Matrix

| Rule | Trigger | Advisory |
|---|---|---|
| Extreme rainfall | 24h rainfall `>= 100 mm` or PAGASA warning | Suspend field work, secure harvest, activate LGU/DRRM coordination |
| Heavy rain harvest risk | 24h rainfall `>= 20 mm` during ripening/harvest | Defer harvest, use mechanical drying, protect grain |
| Fertilizer defer | 24h rain `>= 15 mm` or forecast heavy rain in 24-48h | Delay basal/topdress fertilizer by 2-3 dry days |
| Spraying defer | Rain `>= 5-10 mm`, high wind, or rain forecast | Reschedule pesticide/foliar spraying |
| Dry spell watch | CDD 10-13 | Monitor rainfed crops, prepare supplemental irrigation |
| Dry spell warning | CDD 14-20 | Prioritize reproductive-stage crops, coordinate water support |
| Critical dry spell | CDD `>= 21` in rainfed areas | Emergency irrigation, seed buffer, crop damage validation |
| Heat high | WBGT high or Tmax threshold | Avoid field work during hottest hours, livestock water/shade |
| Heat danger | WBGT danger | Suspend field work 9 AM-4 PM, RHU/MAO coordination |
| Wet spell disease | CWD `>= 3-5`, RH `>= 80-90%` | Intensify pest/disease scouting |
| Planting suitable | Onset met, rainfall adequate, no heavy rain forecast | Proceed with planting/land prep |
| Planting defer | Below-normal rainfall or dry spell during window | Delay rainfed planting or shift variety |
| Drying unsuitable | Rain expected, RH high, low solar | Use mechanical drying/storage |

## 10. UI/UX Recommendations

- Design for scanning: one row per municipality with clear risk color, source date, and action.
- Put action text before raw weather values for field users.
- Use official/source badges and "last updated" labels everywhere.
- Provide uncertainty and data-lag labels for NASA/satellite products.
- Keep advisories explainable: show rule, threshold, observed value, source, valid period.
- Add print/export for LGU advisories and municipal bulletin PDFs.
- Add low-bandwidth mode: table-first, compressed GeoJSON, minimal charts.
- Avoid exposing personal farmer-level data; use aggregated exposure counts.

## 13. Deployment Instructions

1. Publish the repository through GitHub Desktop.
2. Confirm `.github/workflows/daily_pipeline.yml` is present.
3. In GitHub repository settings, enable Actions write permission if the bot will commit data updates.
4. Enable GitHub Pages from branch `main`, folder `/frontend`.
5. Manually run the GitHub Action once from the Actions tab.
6. Confirm the workflow creates/updates `data/processed`, `data/geospatial`, `data/advisories`, and `data/pipeline_status.json`.
7. Visit the GitHub Pages URL and check data freshness.
8. If adding Supabase, store service role keys only in GitHub Actions secrets, never in frontend JavaScript.

## 14. AI Advisory Layer Later

Start with rule-based advisories only. Add AI later as a drafting assistant that:

- Receives structured facts, rules triggered, municipality, crop stage, source dates, and allowed recommendation templates.
- Produces draft language only, not the final hazard decision.
- Always displays rule IDs and source values used.
- Requires reviewer approval for official public release.
- Never invents PAGASA warnings, damage reports, affected hectares, or farmer counts.
